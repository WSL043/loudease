# LoudEase governance

LoudEase is a founder-led open-source project. Open collaboration does not require shared ownership of the official project.

## Project lead

WSL043 is the Project Lead and has final responsibility for:

- roadmap and product direction;
- accepting, modifying, reverting, or declining contributions;
- security response and disclosure timing;
- appointing or removing maintainers and repository access;
- official releases, signing, Chrome Web Store publishing, domains, and project accounts;
- use of the LoudEase name, logo, and other project marks.

Issues, pull requests, translations, testing, sponsorship, or other contributions do not automatically create governance rights, repository access, maintainer status, or ownership of the official project.

## Maintainers

Maintainer access is granted by the Project Lead based on sustained, trustworthy work and the minimum permissions needed. Access may be changed or removed when responsibilities change, security requires it, or the maintainer is no longer active.

External contributors should use issues and pull requests. Direct pushes to protected branches are not part of the normal contribution path.

Maintainer candidates are evaluated from sustained, technically sound participation: reproducible issue work, focused reviews, regression-backed changes, careful handling of privacy and permissions, and respectful community support. Appointment remains explicit; contribution count alone does not grant access.

## Decisions

Technical decisions should be supported by reproducible evidence, especially for DSP, privacy, permissions, security, and compatibility claims. Maintainers should explain material decisions in an issue, pull request, or canonical project document when practical.

The Project Lead resolves deadlocks. This authority does not remove or narrow any right that recipients already have under GPL-3.0-only.

## Contributions and copyright

Contributors retain copyright in their contributions and license accepted work under GPL-3.0-only. Each commit must carry a DCO sign-off as described in [CONTRIBUTING.md](CONTRIBUTING.md).

The DCO is not a copyright assignment and does not grant a separate proprietary relicensing right. If the project ever requests broader relicensing permission, it must use a separate, explicit agreement that is not a condition for ordinary issue reports, testing, or non-code participation.

## Official identity

Forking and redistribution are rights granted by the software license. Official status is separate: modified distributions must follow [TRADEMARKS.md](TRADEMARKS.md), use a distinct name and visual identity, and must not imply endorsement or official release status.

Only the Project Lead or an explicitly authorized release maintainer may publish an official LoudEase build.

## Changes to governance

The Project Lead may update this governance document as the project grows. Governance changes do not retroactively alter copyright ownership, accepted contribution licenses, or rights already granted under an open-source license.
