# 持续轻声额外补偿反例：2026-09-23

结论：**拒绝这次额外补偿试验，不装入开发版或正式 DSP。**它在人工波形上能抬高想要的轻声，却以几乎相同幅度抬高同电平的环境底声；仅凭现有数值观察器无法区分两者。用户当前加载的 0.92 开发候选保持原样；没有重载扩展、停止捕获、改系统音量、提交或发布。

## 假设与方法

[三平台九条正片现场报告](PERSONAL_CHROME_DYNAMICS_092_20260923.md)显示，部分持续轻声窗口低于内部 `-19±2 dB` 范围，而控制器目标增益与实际增益通常接近。为检验一个比继续提高全局动态系数更窄的办法，`node tools/sustained_quiet_experiment.js` 只在内存中为策略试插入最多 `+2.5 dB` 的修正：节目参考高于 400 ms 电平至少 4 dB、3 s 电平低于约 -29.5 dB 且高于轻声底线时逐步加入。原 16 dB 动态提升、总增益及峰值预算上限依旧执行。一次性副本把现有 3 s 电平传入策略；生产和 `dist/github-dev` 文件均未改变。

脚本对同一人工 PCM 比较原策略与试验策略，并通过 `analyze_personal_quality.js` 原有页面、捕获状态、音量、缺口、热身、来源及策略筛选，对此前保留的真实 Chrome 数值行做**请求量反事实**。反事实只估计“可能多请求多少增益”，不重新渲染网站音频，不能推断实际输出、语义或听感。原始量化文件在 `tmp/transition-crest-candidate/sustained-quiet-experiment.json`；现场原始失败和不足时长窗口保留不动。

## 结果

| 48 kHz 人工情景，均取末段同口径 3 s 电平 | 原输出 dB | 试验输出 dB |
|---|---:|---:|
| 单独稳定轻声节目 | -20.00 | -20.00 |
| 普通节目后持续轻声，末段输入约 -33.73 | -21.81 | -20.05 |
| 普通节目后同电平多频环境底声，末段输入约 -33.77 | -21.81 | -20.05 |
| 普通节目后深度底声，末段输入约 -44.18 | -36.47 | -36.47 |
| 轻声突变大声 | -17.59 | -17.59 |

上述波形无硬削波，但这不构成 true-peak 或听感验收。多频环境底声被额外抬高约 **1.76 dB**，与目标轻声的 **1.76 dB** 几乎相同；这与避免误抬节目内底声的产品目标冲突。即使底线挡住更深的底声，也解决不了与目标内容同电平的底声。

“可多请求”还考虑了动态提升上限和估计的峰值预算空余，但使用观察器瞬时电平近似策略输入；独立的快速压低和实际限幅可能进一步减少输出变化。它不是“会进入目标区间”的行数。尤其另一条上海视频和抖音海岛多数偏低窗口不符合该触发条件，局部补偿不能解决整个数值分布。

现有 0.92 候选因此仍未通过内部数值验收，也尚无单标签听感或停止捕获后的原生输出恢复证据。严格工程 true-peak 审计维持 **9/24** 失败；已有 4x 检测器仅为[离线候选](TRUE_PEAK_CANDIDATE.md)，其浏览器成本和听感门槛尚未满足，不能借本试验顺便启用。下一次算法决策需要区分真实语音与环境底声的有效证据，以及用户对当前版本的实际听音反馈；不能从 `-19±2 dB` 实验数字直接宣称需要把每段底声抬进范围。
