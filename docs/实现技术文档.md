# LoudEase 实现技术文档

本文对应 `0.7.2` 当前代码。运行时代码与可执行测试是最终事实来源。

## 1. 产品边界

扩展处理的是标签页音频，不是系统总线音频。公开商店构建仍要求用户调用扩展后启动 `tabCapture`。受信任的 GitHub 开发构建可以在 Chrome 进程启动时通过精确扩展 ID allowlist 获得额外授权，并在抖音、B站、YouTube 的早期导航阶段接管；商店构建会物理移除这条自动编排路径。

主链路：

```text
用户点击扩展 / GitHub 构建收到 Chrome 启动授权
  -> background 获取一次性 tabCapture streamId
  -> offscreen 消费 MediaStream
  -> programme-leveler-v4 AudioWorklet
  -> 播放器音量边界
  -> 本机输出
```

旧的页面级 `createMediaElementSource()` 引擎已退出运行时。`content/bridge.js` 只观察媒体数量、播放状态、静音和播放器音量，不处理 PCM。

## 2. 模块职责

- `background.js`：用户手势或 GitHub 启动授权、streamId、共享的 offscreen 创建生命周期、多标签 session 编排、设置和状态聚合。并发标签只发起一次 offscreen 创建。
- `content/bridge.js`：轻量页面观察，提供播放器音量、媒体状态和本地节目指纹。
- `offscreen/index.js`：每个标签页的 `CaptureSession`、AudioContext、工作线程和清理。
- `offscreen/leveler-worklet.js`：正常路径中的计量、节目估计、增益包络、播放器边界和前视限幅。
- `offscreen/meter-worklet.js` / `limiter-worklet.js`：统一 worklet 加载失败时的保守降级组件。
- `popup/`：授权入口、真实状态、双强度控制和恢复操作。
- `monitor/`：高级设置、诊断导出和开发版本机诊断发送开关；发送偏好与接收器是否真正在线分开显示。
- `shared/core.js`：设置、计量和播放器边界工具。
- `shared/programme-leveler-policy.js`：主 worklet 与降级路径共用的节目门控估计、稳定节目基线、有限细节提升与快速保护策略。

## 3. DSP

工作线程以 20 ms 为一帧，维护 400 ms momentary、3 s short-term 诊断窗，以及每 100 ms 更新一次的常量内存节目响度直方图。节目估计使用 `-70 dB` 绝对门和相对当前未门控均值低 10 dB 的相对门；它从节目开始累计，不是会追着主歌、副歌或电影场景移动的 10–30 秒滚动目标。

输入经过近似 K-weighting，峰值安全仍使用原始样本。控制策略把“节目整体偏大或偏小”的基线修正与“节目内部的小声细节”分开：当前产品中心为 `-19 dB`，这是 `-20/-19/-18/-16 dB` 同条件校准后普通素材开关偏差最小的候选；节目基线最大提升 `25 dB`、最大压低 `24 dB`。清晰可听的内部正向细节修正最多额外 `16 dB`，并在 `-40 dB` 到 `-48 dB` 之间逐步失去资格，防止响节目里的停顿和底噪被当成另一个安静节目抬到满档。向上节目基线约用 1.5 秒连续有效信号建立完整置信，快速大声保护则无需等待。所有决定仍只进入一条声道联动增益包络，提升还受原始峰值余量与最多 `10 dB` limiter 预算约束。

冷启动时立即允许快速压大声，但前 400 ms 不猜测提小声；连续有效节目约 1.5 秒达到完整提升置信度。统一包络为：压低 attack 20 ms / release 250 ms，提升 attack 180 ms / release 120 ms，每 20 ms 最多向上移动 3 dB。超过一秒的静音会回到已测得的节目基线，而不是回到 unity 后让下一段重新跳一次。

最终使用 5 ms 前视、声道联动的 sample-peak limiter，默认 ceiling 为 `-3 dBFS`。跳变时使用固定的“节目中心 + 6 dB”安全 crest，并按压大声强度缩放、保持 40 ms；它不再根据刚才的安静输出继续下压下一声。这取代旧的固定 `-24 dBFS` 深压和会随安静片段泵动的 recent-peak ceiling。当前尚未做 4x 过采样真峰值估计。

## 4. 播放器音量

播放器静音或音量为零时输出硬静音。播放器音量状态可靠时：

- 提小声预算随播放器音量降低；
- limiter ceiling 同比降低；
- 扩展不修改网页的 `media.volume`。

状态未知或冲突时，默认禁止向上增益，保留向下保护。这个边界只能约束软件输出，不能控制系统、声卡、功放或耳机声压。

## 5. 多标签与切源

每个已经捕获的标签页在 offscreen 中拥有独立 session。切换浏览器焦点不会停止已有 session；多个标签同时恢复时会等待同一个 offscreen 创建 Promise，再分别建立 session。GitHub 自动保护在目标 URL 导航和受保护页面打开新标签时提前请求同一条 tabCapture 链路，不会创建页面级 PCM 处理器。站点更换 `<video>`、直播流或 SPA 路由时，tabCapture 仍跟随标签页混合输出，不需要重新绑定媒体元素；页面 URL 或活动媒体源指纹变化时，会清空节目累计和继承增益，避免上一条安静视频的提升泄漏到下一条大声视频。暂停时保留最后一次有效节目指纹，暂停/恢复本身不会误清空状态。

## 6. 状态真实性

popup 只有在以下条件成立时才显示正在处理：

- capture session 处于 active/processing；
- worklet 已上报 signal tick；
- meter 状态仍在 TTL 内；
- 没有 mute、错误或停止状态覆盖。

开关打开只代表用户意图，不等于音频已经接管。

## 7. 构建与隐私

仓库提供两个 allowlist 构建：

- `dist/github-dev`：保留默认关闭的 localhost 开发诊断和启动 allowlist 自动保护；
- `dist/store`：删除 localhost 权限、诊断与自动保护代码。

商店验证器会拒绝开发目录、日志、密钥、压缩包、动态执行、localhost 字符串和缺失引用。音频样本始终留在本机 Web Audio 图中。
