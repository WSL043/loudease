# 参数说明和调整思路

## 0.4.57 当前逻辑

插件现在不是“先学习一段再决定怎么调”，而是实时向同一个听感音量靠拢：

- 每约 8ms 采样一次当前波形响度和峰值，前视延迟为 0ms。
- 主音量判断使用约 400ms 听感窗口，避免追着每个瞬时波峰来回调音量。
- 大声、尖峰、瞬时过响仍会立即压低。
- 小声使用单独的提升目标，会比早期版本更明显，但只在最近峰值余量充足时提升。
- 小声默认最多提升 34 dB，但仍受峰值余量和 limiter 限制，避免把底噪、破音和失真一起放大。
- 弹窗里的“压大声”和“提小声”两条强度滑条会实时影响这两类处理强度。
- 两个强度都为 0 时会走 dry 原声旁路；启动保护、JS 增益、原生 compressor 和 limiter 都不会再压声。
- 只要“压大声”或“提小声”任一开启，输出链路都会保留安全 limiter；提小声不会因为压大声为 0 而失去防爆保护。
- 输出链路有更低的启动保护、播放前接管钩子和 limiter 兜底，用来减少声音先冲出来再被压的感觉。

## 为什么小声不能无限拉大

小声提升会同时放大底噪、呼吸声、环境噪声、压缩失真和原视频本身的破音。  
所以插件会强制向目标响度靠拢，但不会无视安全余量硬拉：

- 声音太接近静音时不提升。
- 当前峰值已经偏高时不提升。
- 已经触发压低时不提升。
- 提升上限比上一版更高，但会被峰值余量动态限制，优先避免破音。

## 不超过整体安全上限

播放器音量和系统音量仍然是最终上限。插件不会修改网页播放器自己的音量，只在 WebAudio 链路里做实时增益控制。  
小声提升后仍然会经过 limiter，避免突然爆音。
