# LoudEase 音量平衡目标与现场复核：2026-09-23

LoudEase 要解决的是用户选定整体聆听音量后，视频内对白/音乐与响亮段落、以及换视频时的**相对响度落差**。系统和播放器音量仍由用户决定；扩展不应把每个安静时刻拉成同一个电平，也不能让响声反而比轻声更低。产品介绍、[DSP 评价约定](DSP_EVALUATION.md)和用户此前提出的“轻声提升、大声压低、换片衔接”应以这个目标共同解释。

## 验收口径

1. **跨视频节目中心**：同一播放器音量意图下，比较不同视频的同口径输入/输出整体中心及跨度。此前讨论的“尽量不超过约 3 dB”是产品试验目标，不是行业标准；真实视频不同、并行播放和无配对 A/B 时只能作为诊断。
2. **视频内层次**：在相同时间窗中比较输入较轻组与较响组的输出差，确认落差缩小而未反向、未被抹平。突发峰值由独立安全路径评价，不能要求所有 3 秒窗口进入 `-19±2 dB`。对于**已标注为人声或音乐前景**的稳定段，可继续用该内部范围检查提升/压低是否明显；背景、停顿和刻意安静段不计这种目标命中率。
3. **切换与安全**：从实际新视频有效发声开始量适应时间，记录是否继承旧增益、是否短促过响、增益/限幅轨迹、输出中断、样本峰值和严格工程 true-peak。网页加载时间不是响度稳定时间。
4. **用户控制**：播放器静音/零音量必须立即安静，用户降低播放器或系统音量不能被扩展反向抵消；停止捕获后原生输出恢复要单独验收。

[EBU Tech 3342](https://tech.ebu.ch/docs/tech/tech3342.pdf)将节目整体响度、响度范围和最大 true peak 视为互补量；其范围算法会排除一部分背景/静音，并使用短时电平分位数，避免单次枪声或淡出决定整段范围。这支持上述**分开看中心与层次**的方法，但本项目观察器并非合规 EBU 仪表，也不能凭电平自动识别人声。

## 九条真实视频的重新分析

`node tools/analyze_balance_objective.js tmp/personal-quality-20260923-033648` 复用[既有个人 Chrome 合格行](PERSONAL_CHROME_DYNAMICS_092_20260923.md)的页面推进、捕获运行、来源/策略、播放器音量、热身和丢行筛选。输入输出都是一次性 PCM 不变观察器的同口径近似 K 加权 3 秒窗口，按可核实的播放器音量补偿。新报告在 `tmp/personal-quality-20260923-033648/balance-objective.json`。相邻 0.1 秒窗口彼此重叠，不能当作独立听音样本。

九段的输入节目中心跨度约 **19.04 dB**，输出约 **3.54 dB**：跨视频平衡有实质效果，但这九段尚未达到此前提出的约 3 dB 试验目标。每段的内部范围使用**同一输入条件选出的时间窗**，避免输入、输出分别过滤后比较不同内容；它受 [EBU 的相对门限思路](https://tech.ebu.ch/docs/tech/tech3342.pdf)启发，却不是标准 LRA。

| 实例 | 输入较响组−较轻组 | 对应输出较响组−较轻组 | 含义 |
|---|---:|---:|---|
| YouTube 北京旅行 | +6.91 dB | +0.45 dB | 层次接近被抹平，须复核 |
| B站 mini 沙二 | +6.42 dB | **−0.63 dB** | 数值上出现次序反转，须复核 |
| YouTube 上海独旅 | +9.63 dB | +2.58 dB | 落差缩小且仍保留差异 |
| 抖音海岛盲盒 | +13.56 dB | +8.40 dB | 落差仍大；不能只用一个系数拉平所有素材 |

这些组按输入 3 秒电平的上下四分位选取，不是“对白/环境声”的语义标签，也不是即时样本级因果关系。B站反转是工程警报，不等于已经证明用户会听到音量反转。该片较轻组的目标/实际增益中位约 `+3.06/+3.04 dB`，较响组约 `−0.99/−2.68 dB`；后一组两个中位数相差约 1.69 dB，与快速压低、较慢恢复造成的持续偏低相符，但尚未单独证明机制。不能仅靠继续加大轻声提升处理。

现行动态项约为 `−0.92 × (400 ms 响度−节目参考)`。暂时忽略死区、峰值保护、限幅及节目参考随时间变化时，输出的同片响度变化只留下输入变化的约 **8%**；这解释了它为何容易接近抹平，但不等于九条真实视频实际只剩 8%。合格现场数值的目标分解显示，B站 mini 沙二较响组基础目标增益中位约 `−0.96 dB`，实际约 `−2.68 dB`；约 24% 的较响组记录还有超出基础目标的快速保护/余量约束。现有记录没有逐采样 PCM 和完整快速保护轨迹，无法把 1.7 dB 差额全归给某一个环节。

原 `0.86` 开发候选的另一批九段输出节目中心跨度约 **3.99 dB**，也有接近抹平/反转的实例；素材与播放位置并不配对，**3.99→3.54 dB 不能归因于 0.92 优化**。当前 `0.92` 仍是未发布试验候选，既不能称为产品听感通过，也不应再按“所有 3 秒窗口命中 -19±2 dB”单指标调大系数。[额外持续轻声补偿](SUSTAINED_QUIET_COUNTERFACTUAL_20260923.md)因同幅抬高环境底声已被拒绝。

## 控制路径判断与下一步实现

现有三个职责应继续分明：节目边界重置后建立缓慢基线；有证据时适度缩小同片落差并保持前景层次；突发过响在快速保护/前视限幅路径处理。B站较响组的目标与实际增益偏差值得作为**恢复包络**的独立候选，而不是混入新的全局提升。一个离线试验把压低恢复时间从 250 ms 缩至 80 ms：周期突发声的目标−实际增益差从约 2.87 缩到 0.72 dB，但 3 秒输出仅提高约 0.34 dB；它本身不足以解决问题，抽吸、听感和真实浏览器表现未验收，**没有装入扩展**。原始试算在 `tmp/transition-crest-candidate/cut-release-experiment.json`。

另一个纯离线对照使用同一受控 48 kHz PCM，分别试了当前 `0.92/0.92`、温和的 `0.65/0.65`、轻声 `0.80`/响声 `0.50`，以及后一组合加快恢复到 120 ms。原输入轻/响段差约 `6.0–6.7 dB`，输出差从当前约 `1.9–2.4 dB` 变为候选约 `2.6–3.4 dB`；底声段仍约 `−58 dB`，没有被候选额外抬高。真实 YouTube 轻声组的旧目标动态提升中位可达 `13 dB` 以上，统一把系数降到 `0.65` 也可能削弱应该保留的对白。因此这些数值只说明调参的取舍，**不能证明新系数更好**，也未写入运行代码。原始受控输出在 `tmp/transition-crest-candidate/balance-dynamics-counterfactual.json`，现场目标分解在 `tmp/personal-quality-20260923-033648/balance-telemetry-policy-probe.json`。

下一步优先复核快速保护触发与释放造成的持续压低，再决定是否降低动态项；不能仅改一个全局系数。DSP 候选应在同一合法 PCM 上成对比较现用路径、候选与旁路：安静对白、音乐、密集音效、稀疏环境声、周期突发和视频边界各自记录节目中心、对应时间窗内的轻/响差、增益恢复、峰值及失真。只有改进“较响组被持续压低”且不牺牲突发保护、安静内容可懂度、背景底线、播放器音量意图和 Chrome 工作负载，才准备开发版让用户重载并重做三平台真实视频测试。没有自动语义标签或原始音频的当前九段记录，不足以宣称哪个偏低窗口是应该被提升的对白。

严格工程 true-peak 审计仍有 **9/24** 失败；[离线检测器候选](TRUE_PEAK_CANDIDATE.md)尚有浏览器成本和听感门槛。原生输出恢复尚未在用户保持捕获的浏览器中验证。本轮未更改运行 DSP、`dist/github-dev`、浏览器配置、用户系统音量，也未发布版本。
